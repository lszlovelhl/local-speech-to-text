## 六、已知边界与诚实口径（面试主动说明，不要藏）

> 这些不是 bug，而是选型与约束的如实说明，主动讲反而体现工程判断力。

1. **模型精度天花板**：使用 faster-whisper **small**（CPU int8）。中英强混说、方言口音、极短促发音仍可能出现错字；harness 规则层只能修“已知错误模式”，无法突破模型能力上限。若演示环境允许，可对比说明 base/small/medium 的速度—准确率权衡。
2. **为什么不上 medium**：本机 CPU 推理 medium 延迟过高、内存占用大，体验反而差；small 在准确率与速度间取平衡，符合题目“CPU 可运行”约束。
3. **历史数据生命周期**：元数据 localStorage + 音频 blob IndexedDB，最多 20 条、24 小时自动清除；清除浏览器缓存或无痕模式会丢失，属本地单机工具的合理取舍，不做账号体系。
4. **无登录 / 多用户 / 跨域（CORS）**：题目定位本地 B/S 单机工具，同源部署；刻意不引入认证与 CORS，避免过度设计。
5. **真实模型用例默认跳过**：保证 `pytest` 快速稳定；现场可用 `pytest -m real_model` 证明真实识别链路。

## 七、演示前操作清单

### 7.1 启动步骤（评委拿到源码后）

```bash
cd local-speech-to-text
./start.sh            # macOS；Windows 双击 start.bat
# 浏览器自动打开 http://127.0.0.1:8000
```

- 首次运行：脚本自动建虚拟环境、装依赖、检测并下载模型；模型就绪后再识别；
- 若 `models/faster-whisper-small/` 缺失，先执行 `./download_model.sh`；
- 服务异常退出后重新执行 `./start.sh` 即可。

### 7.2 推荐演示动线（约 3 分钟）

1. **界面观感**：切换深浅色按钮、两种模式主题色与录音机拟物造型；
2. **单次识别**：点开始录音说一句中文 → 停止 → 展示文本、语言、分段时间戳；
3. **文件验证**：上传 `samples/chinese.wav` 与 `samples/english.wav`，展示进度条与中英分别识别；
4. **语言控制**：切 English 模式说英文，确认不再混入中文；
5. **会议模式**：持续说话停顿切片 → 文本累积 → 停止后历史磁带可回放；
6. **容错演示**：故意选一个错误格式文件，展示中文友好提示而非报错栈；
7. **工程收尾**：`pytest -q` 展示 23 passed；打开 `docs/` 对照需求实现表。

### 7.3 现场异常应急

| 现象 | 处理 |
|------|------|
| 麦克风无反应 | 检查浏览器地址栏权限；换 `https` / `localhost` 之外的 127.0.0.1 在部分浏览器受限，可用 `localhost` 打开 |
| 首条识别很慢 | 模型首次加载 int8 量化需数秒；后续请求命中缓存，速度正常 |
| 端口 8000 被占 | `start.sh` 有端口预检提示；先结束占用进程再启动 |
| 识别出繁体 | harness 的 OpenCC 会自动转简体；若个别词未覆盖属规则层已知边界 |
