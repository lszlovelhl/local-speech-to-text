# 需求理解与功能拆分

## 一、需求概述

开发一个 B/S 架构的本地语音识别 Web 系统。用户通过浏览器麦克风录音或上传音频文件，后端使用本地开源 ASR 模型将语音转换为文字并返回页面展示。支持中英文自动检测、会议模式实时识别。

## 二、功能拆分

### 必做功能

| 编号 | 功能 | 状态 | 说明 |
|------|------|------|------|
| F1 | 浏览器麦克风录音 | 已实现 | MediaRecorder API，无时长硬限制，状态与时长显示 |
| F2 | 音频文件上传 | 已实现 | WAV/WebM/OGG/MP3/M4A/FLAC，与录音共用后端识别逻辑 |
| F3 | 本地中英文 ASR | 已实现 | faster-whisper small 模型，CPU 推理，auto 自动语言检测 |
| F4 | 识别结果展示 | 已实现 | 语言、状态、文字、音频时长、处理耗时、复制按钮 |
| F5 | 异常处理 | 已实现 | 权限拒绝、无麦克风、空文件、格式不支持、模型失败等 |

### 加分功能

| 编号 | 功能 | 状态 | 说明 |
|------|------|------|------|
| F6 | 实时语音识别 | 已实现 | 会议模式：VAD 自适应切片，停嘴自动识别，文字实时追加 |

### 额外优化

| 功能 | 说明 |
|------|------|
| 自动语言检测 | 默认 auto 模式，中英文混说无需手动切换 |
| VAD 自适应切片 | 浏览器硬件降噪 + 自适应音量阈值 + 最短/最长保护 |
| 会议模式 | 持续录音，VAD 检测停嘴切片，文字实时追加 |
| 苹果风格 UI | SF Pro 字体、毛玻璃卡片、iOS 分段选择器、移动端响应式 |
| 一键启动 | start.sh / start.bat，自动装依赖 + 开浏览器 |

## 三、必要假设与边界条件

1. **录音格式**：浏览器 MediaRecorder 输出 WebM/Opus，后端 PyAV 原生解码
2. **语言模式**：默认 auto 自动检测，也可手动选 zh/en
3. **并发**：单用户场景，串行处理
4. **模型**：Whisper small（244M 参数，~460MB），CPU int8 量化
5. **音频存储**：不持久化，识别后即删临时文件
6. **不做的事**：用户登录、历史记录、说话人识别、语音翻译、TTS、手机端适配
