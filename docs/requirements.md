# 需求理解与功能拆分

## 一、需求概述

开发一个 B/S 架构的本地语音识别 Web 系统。用户通过浏览器麦克风录音或上传音频文件，后端使用本地开源 ASR 模型将中文或英文语音转换为文字并返回页面展示。

## 二、功能拆分

### 必做功能

| 编号 | 功能 | 状态 | 说明 |
|------|------|------|------|
| F1 | 浏览器麦克风录音 | 已实现 | MediaRecorder API，60秒上限，状态与时长显示 |
| F2 | 音频文件上传 | 已实现 | 支持 WAV/WebM/OGG/MP3，与录音共用后端识别逻辑 |
| F3 | 本地中英文 ASR | 已实现 | faster-whisper base 模型，CPU 推理，中英文手动切换 |
| F4 | 识别结果展示 | 已实现 | 语言、状态、文字、音频时长、处理耗时、复制按钮 |
| F5 | 异常处理 | 已实现 | 权限拒绝、无麦克风、空文件、格式不支持、超60s、模型失败等 |

### 加分功能

| 编号 | 功能 | 状态 | 说明 |
|------|------|------|------|
| F6 | 实时语音识别 | 未实现 | 基础分片方案预留了接口，受限于开发周期未完成 |

## 三、必要假设与边界条件

1. **录音格式**：浏览器 MediaRecorder 输出 WebM/Opus 格式，后端 faster-whisper 通过 PyAV 原生解码，无需额外转换。
2. **语言模式**：采用手动选择 zh/en，不做自动语言检测（自动检测属于加分项）。
3. **并发模型**：单用户场景，后端串行处理识别请求，不做并发队列。
4. **模型选择**：使用 Whisper base（74M 参数，约 150MB），在普通笔记本 CPU 上 5 秒音频约 1-2 秒完成识别。
5. **音频存储**：不持久化存储音频文件，识别完成后立即删除临时文件。
6. **不做的事**：用户登录、历史记录、说话人识别、语音翻译、TTS、手机端适配。
